# Contributing

Contributions are welcome after the public release.

Please:

1. open an issue describing the proposed change;
2. preserve existing frozen scientific controls unless a change is explicitly versioned;
3. add or update automated tests;
4. document any change to measurement semantics, policies, seeds, transformation generation, or report schema;
5. avoid committing private datasets, credentials, API keys, or personal machine paths.

Scientific behavior changes should be accompanied by a new version and a clear changelog entry.
